# 주문 로직 — 전체 설명 (상황별·예시)

> 봇이 **언제·어느 방향으로·몇 계약을** 주문하고, 장운영·각종 옵션에 **어떻게 대응**하는지 풀어 쓴 문서.
> 기준 코드: `executor.py`(집행 엔진·reconcile), `targets.py`(목표계약수), `market_state.py`(장운영), `datastore.py`(포지션·미체결).

---

## 0. 한눈에 보기 — 전체 흐름

봇은 **시그널이 올 때마다**, 그리고 **주문/체결이 있으면 주기적으로** 아래를 반복한다(이걸 한 번 도는 걸 **reconcile 사이클**이라 함):

```
시그널 수신 → 목표계약수 계산 → 현재 포지션 확인
 → "지금 주문 내도 되나?" 여러 조건 확인
 → 부족분만큼 maker 지정가 1건 주문
 → 인터벌 대기 → 체결됐으면 반영 / 안 됐으면 취소·재호가 → 다시 확인
```

핵심 원칙 3가지:
1. **목표를 향해 조금씩 맞춰간다** — 한 번에 몰아넣지 않고 `1회주문계약수`씩.
2. **미체결이 남아 있으면 새 주문을 절대 안 낸다** — 이전 주문이 (a)전량체결 되거나 (b)인터벌 지나 취소·확인될 때까지 기다린다. (주문 폭주 방지)
3. **접속매매 구간에서만** 주문한다 — 동시호가·정지·마감엔 안 낸다.

---

## 1. 목표계약수 — 얼마를, 어느 방향으로?

시그널이 오면 **목표 포지션(계약수)** 을 계산한다. (자세한 공식은 `risk-management.md` 참고)

```
C(달러노출선물계약수) = trunc(계좌달러노출액 / 환율 / 10000)
D(포지션헤지비율)     = −floor(코인포지션합 × 헤지비율 / 환율 / 10000)   (Meme면 부호 반대)
목표계약수 = C + D
```

**방향은 목표계약수 자체가 아니라 "목표 − 현재포지션"의 부호로 정해진다.**

- 예) 목표 **+10**, 현재 **0** → 차이 +10 → **매수** 방향
- 예) 목표 **+10**, 현재 **+13** → 차이 −3 → **매도**(줄이기) 방향
- 예) 목표 **−5**, 현재 **+2** → 차이 −7 → **매도**(숏으로) 방향

> 즉 시그널은 "이만큼 보유해라(목표)"만 주고, 봇은 **현재와의 차이를 메우는 방향**으로 주문한다.

## 2. 주문이 나가기까지 — 순서대로 확인하는 조건들

한 reconcile 사이클에서 아래 순서로 확인한다. **하나라도 걸리면 그 사이클은 주문 없이 끝난다.**

### ① 시그널이 있나?
아직 시그널을 한 번도 못 받았으면 → **대기**. (`시그널 없음`)

### ② 지금 주문가능시간인가? (3단 게이트)
`risk-management.md`의 장운영 게이트. 셋 다 통과해야 함:
1. **세션**: 지금이 주간(08:45~15:45)/야간(18:00~06:00) 세션인가? 장외면 차단.
2. **사용자 시간창**: 화면에 설정한 주간/야간 주문가능시간 안인가?
3. **장운영 국면**: **접속매매**인가? (JIF 실시간 우선, 없으면 시각 폴백)

- 예) **동시호가 시간(예: 15:40)** → 국면=동시호가 → **차단**(`주문가능시간 외`). 목표가 있어도 안 냄.
- 예) 주간 세션 + 시간창 안 + 접속매매 → **통과**.

### ③ '주문' 체크가 켜져 있나? (관찰 모드)
화면의 **'주문' 체크박스**가 꺼져 있으면 = **관찰 모드**. 목표·포지션은 계산·표시하지만 **주문 로직 자체를 안 돌린다**(호가 조회·취소·주문 전부 안 함). 로그도 안 쌓인다.

- 예) 사용자가 '주문'을 꺼둠 → 시그널이 와도 **주문 안 나감**. 잔고·목표만 화면 갱신.

### ④ 체결량 브레이커가 걸렸나?
최근 `체결감시(분)` 안에 누적 체결량이 `체결량한도` 이상이면 → **미체결 전부 취소 + 주문 자동 중지(latch)**. 사용자가 '주문'을 다시 눌러야 재개.

- 예) 한도 20인데 최근 10분 체결이 20 도달 → **모든 미체결 취소하고 정지**. `⚠ 체결량 한도 초과 — 주문 중지`.
- (감시시간 0이면 이 기능은 꺼짐)

### ⑤ 미체결 주문이 남아 있나? — 있으면 새 주문 안 냄 (상태기계)
우리가 낸 주문 중 아직 미체결이 하나라도 있으면 → **새 주문을 절대 안 낸다.** 대신 각 미체결을 이렇게 처리:
- **반대 방향** 주문이면 → **즉시 취소**(잘못된 노출 방지).
- **같은 방향**인데 **주문 인터벌이 지났으면** → 취소(재호가 위해).
- 인터벌 안이면 → **유지**(그대로 체결 기다림).

취소를 요청하면 "취소 확인(미체결에서 사라짐)"을 기다린다. **미체결이 0이 돼야** 다음 주문이 나간다.

- 예) 매수 3계약 주문이 미체결로 있고 인터벌 안 → **그대로 기다림**, 새 주문 없음(`체결 대기`).
- 예) 인터벌 지났는데 안 체결됨 → **취소 요청** → 취소 확인되면 다음 사이클에 재호가.

### ⑥ (미체결 0일 때) 목표에 도달했나? — 수렴
목표와 현재의 차이 `|목표 − 포지션|`가 `1회주문계약수`보다 작으면 → **더 안 냄**(수렴, `stop`). 다음 시그널까지 대기.

- 예) 목표 +10, 포지션 +9, 1회주문 3 → 차이 1 < 3 → **수렴, 주문 안 함**. (딱 맞추려 1계약 안 냄)

### ⑦ 최대잔고한도를 넘나?
새 주문이 **노출을 늘리는데 그 결과가 한도 초과**면 → **보류**(`최대잔고한도 초과`). 줄이는(청산) 방향은 한도 넘어도 허용.

- 예) 한도 100, 포지션 98, 1회 5 → 103 되어 한도 초과 → **보류**(98에서 멈춤).
- 예) 한도 100, 포지션 120(초과 상태), 매도 5 → 115로 **줄이는** 주문 → **허용**.

### ⑧ 호가가 있나?
maker 가격을 못 구하면(호가 공백 과다 등) → **보류**(`호가 없음`).

### → 모두 통과하면: **maker 지정가 1건 주문** (`1회주문계약수`만큼)

## 3. maker 재호가 — 어떻게 체결시키나

봇은 시장가로 던지지 않고 **maker(지정가)** 로 호가에 걸어두고 체결을 노린다. 그래서 "걸어두고 → 기다리고 → 안 되면 옮기는" 과정을 반복한다.

- **주문 가격**: 호가창 기준으로 매수는 매수쪽, 매도는 매도쪽 유리한 지정가(`pricing.py`).
- **주문 인터벌**: 주문을 낸 뒤 `주문 인터벌(s)` 동안 기다린다. 이 안에는 호가가 흔들려도 유지(잦은 취소 방지).
- **인터벌 경과 후**: 아직 미체결이고 **호가가 움직여 내 가격이 낡았으면** → 취소하고 **새 호가로 재호가**.
- **동시 주문 수(max_orders)**: 기본 **1** — 한 번에 1건만. 그게 체결돼 미체결이 0이 돼야 다음이 나간다.

### 상황 예 (maker 흐름)
```
목표 +10, 포지션 0, 1회주문 3, 인터벌 5초
1) 매수 3 @1380.3 주문 → 미체결
2) 5초 대기 (그 사이 체결되면 포지션 +3 반영)
3) 안 체결 & 호가 1380.4로 이동 → 낡음 → 취소 → 취소확인
4) 매수 3 @1380.4 재호가
5) 체결됨 → 포지션 +3 → 다음 사이클에 부족분(+7) 또 매수 3 …
6) 포지션 +9 도달, 차이 1 < 3 → 수렴, 정지
```

## 4. 상황별 시나리오 모음

### 시나리오 A — 정상 매수 진행
- 접속매매 + '주문' 켜짐 + 목표 +10, 포지션 0
- → 매수 3 → 체결 → 매수 3 → 체결 → 매수 3 → 포지션 +9 → 수렴(차이 1). **딱 목표는 못 채우고 근처에서 멈춤**(1회주문 단위 특성).

### 시나리오 B — 동시호가 시간
- 15:40(장마감 동시호가), 목표 있음
- → 게이트 ②에서 **차단**. 주문 안 나감. 칩에 `동시호가`. 15:45 마감까지 대기.

### 시나리오 C — 시그널이 방향을 바꿈 (목표 급변)
- 포지션 +8인데 새 시그널로 목표가 −5로 바뀜
- → 차이 −13 → **매도** 방향. 기존 매수 미체결이 있으면 **반대 방향이라 즉시 취소** → 매도로 전환해 줄여감.

### 시나리오 D — 체결이 안 됨(가격 추격)
- 매수 걸어놨는데 시장이 계속 올라 안 체결
- → 인터벌마다 취소·재호가로 **호가를 따라 올라가며** 체결 시도. (슬리피지 가드는 현재 없음 — 계속 추격)

### 시나리오 E — 한도 근처
- 한도 100, 포지션 98, 목표 150, 1회 5
- → 103이 되어 한도 초과 → **보류**. 포지션 98에서 멈추고 매 사이클 `최대잔고한도 초과` 로그.

### 시나리오 F — 체결 폭주(브레이커)
- 짧은 시간에 체결이 한도 초과
- → **미체결 전부 취소 + 정지(latch)**. 사용자가 '주문' 다시 눌러야 재개(누르면 카운트 리셋).

### 시나리오 G — 주문 거부(증거금 부족 등)
- 주문을 냈는데 거부됨
- → 화면에 `⚠ 주문거부: {사유}` + **지수 백오프**(1→2→4…최대 30초)로 재시도. 원인 풀리면 자동 회복.

### 시나리오 H — 장 마감 후 체결(야간 인수도 등)
- 장 종료로 봇이 주문은 안 내지만 체결 통보가 옴
- → **주문은 안 나가지만 잔고는 갱신**된다(체결 시 포지션 재조회).

### 시나리오 I — 관찰 모드
- '주문' 꺼둠
- → 목표·포지션·잔고만 화면에 표시. **아무 주문·취소도 안 함.**

## 5. 변수(옵션)별 대응 요약

| 옵션/변수 | 역할 | 봇의 대응 |
|---|---|---|
| **시그널(환율·코인포지션합)** | 목표 계산 입력 | 올 때마다 목표 재계산 → 부족분 주문 |
| **헤지비율(B%)·계좌달러노출액** | 목표계약수 결정 | 적용된 값으로 C·D 계산 (입력 도중엔 반영 안 됨, 적용 버튼 눌러야) |
| **1회주문계약수** | 한 번에 낼 수량 | 매 주문 이 수량만큼. 목표 근처에선 이 단위 미만이면 수렴(정지) |
| **주문 인터벌(s)** | 재호가 주기 | 주문 후 이 시간 대기 → 낡으면 취소·재호가. 그 안엔 유지 |
| **최대잔고한도** | 노출 상한 | 늘리는 주문이 한도 넘으면 보류. 줄이는 주문은 허용 |
| **체결감시(분)·체결량한도** | 체결 폭주 차단 | 한도 초과 시 미체결 취소 + 정지(수동 재개). 감시 0이면 꺼짐 |
| **주문가능시간(주/야)** | 거래 허용 시간창 | 창 밖이면 주문 차단 |
| **'주문' 체크박스** | 실주문 on/off | 꺼지면 관찰 모드(주문 안 나감) |
| **장운영 국면(JIF)** | 실제 장상태 | 접속매매만 주문. 동시호가·정지·마감 차단 |
| **종목코드** | 매매 대상 | 근월/차근월 선택. 만기·롤오버 규칙 적용(별도) |
| **SIGNAL_TOKEN(Dalin/Meme)** | 발신처 구분 | 토큰 일치 시그널만 처리 · Meme면 D 부호 반전 · 포트/색 구분 |

## 6. 자주 헷갈리는 점 (요약)

- **목표에 딱 안 맞을 수 있다** — `1회주문계약수` 단위라, 목표 근처에서 그 미만 차이는 안 채우고 수렴한다.
- **미체결이 있으면 새 주문은 절대 안 나간다** — 통보(체결/취소)가 와야 다음이 나간다. 통보가 두절되면 멈춰서 기다린다(폭주 방지).
- **한도는 "증가만" 막는다** — 한도를 낮춰도 이미 초과된 포지션을 자동 청산하진 않는다.
- **주문거부는 멈추지 않고 백오프로 계속 재시도**한다(자동 중지 없음).
- **접속매매가 아니면 아무리 목표가 있어도 안 낸다.**

> 더 깊은 리스크·장운영 규칙은 `risk-management.md`, 목표계약수 공식은 거기 1~2장 참고.
