## 1. 목표

외부에서 들어온 매매 시그널을 받아, **maker(지정가) 주문**으로 집행하는 엔진.
백테스트는 하지 않는다. 실집행이 핵심.

거래 대상: **KOSPI200 야간선물**(KRX 야간파생 18:00~05:00 / CME 연계). 주간도 동일 로직 적용 가능.

## 2. 핵심 동작 (상태머신)

```
[시그널 수신] → 목표계약수 계산(4장)
   │
   ▼  ┌─────────────────── 루프 ───────────────────┐
   └─>│ diff = 목표 − 원달러선물잔고                  │
      │ |diff| < 1회주문계약수 ?  ──예──> [종료]      │
      │   │아니오                                     │
      │   ▼                                           │
      │ 호가공백 규칙으로 가격 계산(4장)              │
      │   · 공백 6이상 → 주문 안 함(다음 사이클 대기) │
      │   ▼                                           │
      │ maker 주문(1회주문계약수, diff부호 방향)      │
      │   ├─ 인터벌 전 "전량체결" → 즉시 루프 처음으로│ (대기 생략)
      │   └─ 인터벌 도달(부분/미체결) → 남은수량 취소 │
      │         → 호가 재조회 → 루프 처음으로(재호가) │
      └───────────────────────────────────────────────┘
```

1. 시그널 수신 → 목표계약수 계산
2. `diff = 목표 − 원달러선물잔고`. `|diff| < 1회주문계약수`면 종료.
3. 호가공백 규칙으로 가격 산출(공백 ≥6이면 주문 안 함). diff 부호로 매수/매도.
4. 1회주문계약수만큼 maker 주문 → 인터벌 동안 체결 감시. 세 경우 모두 **다음주문**으로:
   - ① **전량체결** → 인터벌 안 기다리고 즉시 다음주문
   - ② **부분체결**(인터벌 도달) → 미체결분 취소 → 다음주문
   - ③ **전량미체결**(인터벌 도달) → 미체결분 취소 → 다음주문
   - 체결분은 포지션에 반영 → 다음 사이클 diff에 자동 반영(재호가 시 호가·가격 재계산)
5. 종료조건: `|diff| < 1회주문계약수` / 주문가능시간 종료 / 최대잔고한도 캡. 주간·야간 모두 동작.

## 3. 시그널 수신 프로토콜 — **TCP** (결정됨)

송신측은 같은 공유기(가정 LAN)에 있는 **기존 델파이 프로그램**. 봇은 수신 서버.

### 결정 사항 (델파이 udpchat 예제 분석 후 확정 — `C:\project\VibeCode\udpchat`)
실제 전송은 **UDP 발견 + TCP 메시지 하이브리드**. (우리 "TCP로 시그널 전달" 의도와 정확히 일치)
- **UDP 8888 브로드캐스트** = 피어 발견 + 하트비트(5초). 메시지: `HELLO\t<ID>\t<Name>\t<TCP포트>`,
  `BYE\t<ID>`. 피어 타임아웃 15초. 같은 PC 다중실행 지원(SO_REUSEADDR).
- **TCP(동적 포트, HELLO로 광고)** = 실제 메시지(돈 트리거, 신뢰성). 연결→`<ID>\t<Name>\t<Msg>\n`(UTF-8)→끊음.
- **봇 = 또 하나의 피어**: HELLO 브로드캐스트(송신자가 봇 발견) + TCP 서버(메시지 수신). → `src/trdbot/signal_link.py`
- **Msg 본문 = JSON** (아래 페이로드). 멱등(id) + 토큰 검증.

### 페이로드에 필수로 넣을 4가지 (트리거가 "돈"이라서)
1. **`id` (멱등키)** — 재전송돼도 같은 주문이 두 번 안 나가게. 이미 처리한 id면 무시.
2. **줄단위 구분** (`\n`) — 위 참조.
3. **`token` (공유 시크릿)** — LAN이라도 다른 기기/실수 트리거 차단.
4. **하트비트** — 봇이 송신기 생존을 알아야 함. 끊기면 화면에 경고.

### 시그널에 실려오는 데이터 (결정됨)
델파이가 매 시그널에 아래 4개를 담아 보낸다. **매수/매도는 없음**(방향은 계산). 종목코드·수량·비율은 화면 설정.
1. **날짜시간** (`datetime`)
2. **환율** (`fx`) — 목표계약수 계산용. 화면 환율 표시칸을 이 값으로 채움
3. **토탈잔고 국내총합** (`total_domestic`, KRW)
4. **토탈잔고 코인합** (`total_coin`, KRW)

봇은 이 4개 + 화면의 A%/B%로 목표계약수를 계산(4장 공식). **방향은 `(목표−원달러선물잔고)` 부호로 결정**
(시그널이 방향을 주지 않음). 목표가 음수면 숏.

### 메시지 예시
```json
{"id":"a3f9","token":"xxx","datetime":"2026-06-15T19:30:00","fx":1380.5,"total_domestic":500000000,"total_coin":200000000}
```
envelope: `id`(멱등키) + `token`(공유 시크릿) 필수, 줄단위(`\n`) 구분, 하트비트 별도.

### 향후 옵션 (지금은 안 함)
- 안정성/확장이 더 필요하면 **MQTT(Mosquitto)**로 교체 고려. QoS 1/2 전달보장, keepalive/재연결 내장,
  델파이도 라이브러리 있음. 단점: 브로커 프로세스 추가.

화면 또는 설정파일에서 받는다.

> `token`/`listen_port`은 현재 목업에 칸 없음 — 설정파일/추가칸 결정 필요.

### 목표계약수 모델 (화면 우측 — 비율 기반 포지션 타겟)

화면은 단순 시그널 집행이 아니라 **목표 포지션까지 채우는** 구조다:
**공식 (확정, `src/trdbot/targets.py` 구현·테스트 완료):**
```
달러비율계약수 (C) = +floor( (토탈잔고국내총합 + 수동잔고조정액) × (A/100) / 환율 / 10000 )
헤지비율계약수 (D) = −floor( 토탈잔고코인합 × (B/100) / 환율 / 10000 )    ← 헤지=숏(−)
목표계약수      = (C) + (D)     (|D|>C → 목표 음수 → 숏. 롱/숏 양방향)
```
- **수동잔고조정액**: 화면 "종목·비율 설정" 입력(기본 0, ± 가능). **C에만** 가산(D=코인잔고 영향 없음).
  화면 입력이라 저장/로드되지만 `OrderConfig`에는 미포함(런타임 계산에만 사용). 표시 잔고는 시그널 원값 유지.
- `10000` = 원달러선물 1계약 = US$10,000 (KRX 미국달러선물). (KRW잔고×비율)/환율=USD환산, /10000=계약수.
- A/B는 화면 `%` 입력 → 내부 `/100`(50%→0.5). 각각 **절대값 floor 후 부호**(`-floor(...)`, floor(-x) 아님).
- 검증: 국내5억·코인2억·A50·B30·환율1380 → C=18, D=−4, 목표=**14**. (코인 10억이면 D=−72 → 목표=−54 숏)

maker 엔진은 (현재 원달러선물잔고 → 목표계약수) 차이를 `qty_per_order`씩, `max_position` 한도 내에서 채운다.
**환율·국내잔고·코인잔고는 모두 외부 시그널이 실어 보낸다**(3장) — LS/거래소 조회 불필요.
원달러선물잔고(현재 포지션)만 LS(t0441)에서 조회. 화면 `apply_signal(fx, total_domestic, total_coin)`이
표시칸+목표를 갱신.

### 주문가격 규칙 (확정 — 호가공백 기반, `src/trdbot/pricing.py`)

**자기호가**=내 방향 1호가(매수→매수1, 매도→매도1), **호가공백**=`(매도1−매수1)/틱 − 1`(빈 호가 칸 수).
```
공백 0(공백없음) → 자기호가 ±1틱 (=상대1호가)   공백 3 → ±2틱
공백 1            → ±1틱                          공백 4 → ±3틱
공백 2            → ±2틱                          공백 5 → ±3틱
공백 6 이상       → 주문 안 함 (스프레드 과다 — 슬리피지 가드 역할)
```
- 공식: `offset = floor(공백/2)+1` (공백 0~5), 공백≥6 → None.
- 매수 = 매수1 **+** offset틱(↑), 매도 = 매도1 **−** offset틱(↓).
- 틱은 호가 인접 최소간격으로 역산(주식 차등/ETF 예외 자동, 폴백: KOSPI200=0.05).

### 원달러선물잔고 & 주문방법 (확정)

- **원달러선물잔고(P)** = 최근월물 + 차근월물 포지션 합. **매수 +, 매도 −** (부호 있는 순포지션).
- `diff = 목표계약수(D) − P`
  - `|diff| ≥ 1회주문계약수` → 1회주문계약수만큼 주문. **diff>0 매수 / diff<0 매도**.
  - `|diff| < 1회주문계약수` → 주문 안 함(오버슈트 방지 = 종료조건).
- 체결 타이밍: 전량체결 → 즉시 다음 / 인터벌까지 부분·미체결 → 취소 후 재호가(2장 루프).
- 주간·야간 모두 동작.

### 틱 역산 상세 (가격 규칙의 입력)

- 매 (재)호가 시점마다 호가를 재조회 → 자기호가/상대호가/틱을 새로 구함(가격이 시장을 따라감).
- `tick_size`(호가단위)는 **어떤 TR에도 명시 필드가 없다**(마스터 t8401/t8426/t8455, 시세 t8456,
  호가 t8457 확인. t8455 `tradeunit`은 거래승수 250,000이지 호가단위 아님).
  → **호가 인접 레벨 최소 간격으로 역산**. 라이브 실측 검증:
  | 종목군 | 실측 tick | 비고 |
  |---|---|---|
  | KOSPI200 야간선물(A0169000) | 0.05 | 정액 |
  | 주식(삼성 337k/카카오 40.75k/현대차 647k) | 500 / 50 / 1000 | 가격대별 차등 |
  | ETF(KODEX200/레버리지) | 5 | 정액 — 주식 차등표와 다름 |
  - 역산 1차 + 설정 폴백(호가 성겨 역산 불가 시): KOSPI200=0.05 / 주식=KRX차등 / ETF=5. `min(인접 호가 차이)` = tick.
- 계산가는 **유효 호가 그리드로 스냅**(부동소수 오차 정리). base가 호가에서 온 유효가라 안전.

## 6. 구현 위치

> 레이어 분리: `lsapi` = LS 브로커 클라이언트(순수 API), `trdbot` = 앱/전략 레이어(시그널·UI·집행).
> 의존 방향 trdbot → lsapi 한쪽.

**lsapi (브로커 클라이언트)**: auth · client · config · credentials · endpoints · exceptions · logger · stock · futures · ws_client

**trdbot (앱/전략)**:
- `src/trdbot/order_screen.py` — ✅ 입력 화면(Tkinter). 토글 실행/중지, 입력 저장·로드, `apply_signal()`.
- `src/trdbot/targets.py` — ✅ 목표계약수 산출(C/D/목표). 테스트 완료.
- `src/trdbot/signal_link.py` — ✅ 시그널 수신·송신 피어(델파이 udpchat 호환: UDP발견/하트비트 + TCP).
  `Signal`/`parse_signal`/`SignalLink`(`.send()` 포함). 멱등·토큰 검증. localhost 통합테스트 완료.
- `src/trdbot/pricing.py` — ✅ 주문가격(호가공백 규칙) + tick 역산(`min(역산, fallback)`). 28테스트.
- `src/trdbot/app.py` (+`__main__.py`) — ✅ **메인 런처** `python -m trdbot`. 화면+시그널+집행 배선:

  **seam: `compute_target(signal)→부호목표` 주입**(전략 무관). 들고 온 미체결을 취소·재호가까지 맞춰감(이중주문 방지).
  `tests/test_reconcile.py`·`test_executor.py`.
- `src/trdbot/broker_ls.py` — ✅ BrokerPort 구현(주간/야간/세션라우팅):
  - `LSDayFuturesBroker`(주간, FuturesAPI) — **모의 실측 검증**: 호가 t2112(offerho/bidho, 틱0.10) /
    포지션 t0441(expcode·medosu·jqty) / 주문 CFOAT00100(OutBlock2.OrdNo) / 체결 t0434 chegb='0'(cheqty·ordrem).
    **executor+실주문 end-to-end 검증(롱/숏)**.
  - `LSNightFuturesBroker`(야간, NightFuturesAPI) — 호가 t8457(모의 검증). 주문/잔고는 **LS 공식 명세**:
    포지션 CCENQ90200 OutBlock3(FnoIsuNo·UnsttQty·BnsTpNm) / 주문 CCENT00100(OutBlock2.OrdNo) /
    체결 CCENQ30100 OutBlock3(OrdNo·ExecQty·UnercQty). ⚠️ **모의 야간 주문/잔고 미제공(01900) → 실거래 검증 대기**.
  - `SessionRoutingBroker` — `session_now`(주간 08:45~15:45 / 야간 18:00~06:00)로 어댑터 자동 선택. executor는 세션 모름.
