# TrdBot 진행 상황 (스냅샷)

> 작성: 2026-06-15 · LS증권 OpenAPI 자동매매 봇
> 단일 소스 문서: 집행 설계는 [execution-engine.md](execution-engine.md), 사용법은 [../README.md](../README.md)

## 1. 한 줄 요약

LS증권 OpenAPI(REST+WS) 기반 자동매매 봇. **인증·시세·주문·잔고 API 토대 완성**(모의 실측 검증),
**자동주문화면(Tkinter) 완성**, **목표계약수 공식 확정·구현**, **시그널 송수신(델파이 udpchat 호환) 실기 검증**,
**lsapi(브로커)/trdbot(앱) 패키지 분리**. 남은 핵심은 가격(pricing)·집행 엔진(executor)·메인 런처.

## 2. 전략 개요

외부(델파이) 시그널 → **목표계약수까지 maker(지정가) 주문으로 채우는** 원달러선물 헤지 전략.

```
[델파이 시그널] ──TCP──> [봇] ──목표계약수 계산──> [maker 주문]
                                                      │ N초 미체결
                                                      ▼
                                              [취소→호가 재조회→재호가] (루프)
```

- 시그널이 운반: `날짜시간 · 환율 · 국내잔고 · 코인잔고` (**매수/매도 없음** — 방향은 계산)
- 화면이 제공: `종목코드 · 보유 원달러(계약수) · 헤지비율(B%) · 1회주문계약수 · 주문인터벌 · 최대잔고한도 · 주문가능시간(주/야)`
- 목표계약수 = C + D
  - `C = 보유 원달러` (화면 입력 계약수 ±, 그대로) — 2026-10 변경(예전 A%·수동조정액·금액 환산 공식 폐지)
  - `D = -floor(코인잔고 × B/100 / 환율 / 10000)`  ← 코인 롱→숏 (Meme 토큰이면 부호 반대)
  - 10000 = 원달러선물 1계약(US$10,000). 검증: 보유 원달러 18·코인2억·B30·환율1380 → C=18, D=−4, 목표=**14**
  - |D|>C면 목표 음수 → **숏**(롱/숏 양방향). 방향 = `(목표−원달러선물잔고)` 부호

> 의존 방향 trdbot → lsapi 한쪽(lsapi는 trdbot을 모름).

## 4. 모의 실측으로 검증된 것

- 토큰 발급/캐시(시장별), 자격증명 keyring(DPAPI, `WinVaultKeyring`)
- 주식 현재가 t1102 / 호가 t1101 / 분봉 t8412(sdate·edate 필수, 500건/회)
- 주식 잔고 t0424(모의 예수금 5억) / 미체결 t0425
- 선물 잔고 t0441 / 미체결 t0434
- 야간선물 마스터 t8455(근월 `A0169000`) / 시세 t8456 / 호가 t8457 (야간장 실측: 현재가 1332.20)
- 주식 주문 CSPAT00601 — 장마감 거부(01458)까지 도달, TR/필드 정상 확인
- **tick 역산**(호가 인접 최소간격): KOSPI200선물 0.05 / 삼성 500 / 카카오 50 / 현대차 1000 / ETF 5
- 목표계약수 공식(targets.py): C=18·D=−4·목표=14 검증 (헤지 D는 숏 −, 롱/숏 양방향)
- 자동주문화면: 입력 검증 15/15, 토글, 저장/로드, apply_signal 표시 갱신
- **시그널 송수신 실기**: 델파이 `UDPChat.exe` ↔ 봇 — 피어 발견 + JSON 시그널 수신 + ack 회신 확인
  (localhost 통합테스트: 멱등·토큰 검증, send 경로 포함)

## 5. 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| API | LS OpenAPI (REST+WebSocket) |
| 비밀값 | Windows DPAPI/keyring. .env엔 비민감만 |
| 계좌 | 주식/선물 appkey 분리(LS는 계좌단위 발급). `LSClient(market=…)` |

| 실행버튼 | 토글(실행↔중지). 실행 중 시그널 수신→maker 주문 |
| 화면 | Tkinter 데스크톱 |

## 6. 남은 미정 (executor 착수 전)

1. **슬리피지 가드 한도(X틱)** — 시그널 기준가에서 몇 틱 벗어나면 추격 중단
2. ~~재호가 수량 + reconcile~~ → ✅ **완료**: 매 사이클 `reconcile_plan`이 (반대방향/낡은가격/목표초과)
   미체결을 취소하고 부족분만 재호가. **들고 온 미체결도 재호가 관리**(기동 시 취소 안 함). 0.3초 체결폴링 제거.
3. **종료 조건** — 전량체결 / 최대재호가 / 주문가능시간 종료
4. **코인 잔고/환율 표시칸** — 시그널로 채움(출처 해결). 원달러선물잔고만 LS 조회

## 7. 현재 상태 — 전체 조립 완료

전 모듈 구현·연결됨. 실행: **`python -m trdbot`**
```
[실행 토글] → SignalLink 수신 → app.compute_target(targets) → executor
            → pricing(호가공백) → SessionRoutingBroker(주야) → LS 주문 → 재호가 루프 → 화면 갱신
```

**남은 검증/작업:**
1. **런타임 실측(주간)** — `python -m trdbot` 띄우고 종목 `A7567000`·비율 입력→실행→UDPChat로 시그널 전송 →
   목표 계산·모의 주문·화면 갱신 확인 (모의 day 주문은 검증됨, 통합 GUI 흐름만 미실행)
2. **야간 실거래 검증** — ⚠️ **모의투자는 야간파생 자체를 미지원**(LS 공식 확인 2026-06-18, 01900).
   야간 주문/잔고(CCENT/CCENQ)는 **실거래 계좌에서만** 검증 가능 → 실계좌 1계약 소액으로 필드 확인.
   (야간 시세 t8456/t8457은 모의에서 값이 오지만 주문/잔고가 안 되니 거래검증 불가)
3. ✅ **JIF 장운영 배선 완료** — `tr_cd=JIF, tr_key="0"` 전체구독 → `market_state`(상태머신) →
   executor `in_window`가 동시호가/서킷브레이크/마감에 신규 주문 중단. **페일세이프**: JIF 미수신이면
   기존 `session_now`(현재시각)로 폴백 → WS 끊겨도 동작 동일. 세션 경계(15:45 등) 주문 고아 방지용
   **사이클 세션 고정**(`SessionRoutingBroker`)도 적용.
   - ✅ 모의 WS 포트 버그 수정(9443→환경별 29443/9443). 이거 없으면 모의 실시간 전부 불가였음.
   - ✅ 연결·구독 수락 확인(2026-06-23 09:51, mock, JIF rsp_cd=00000). **구독 시 현재상태 스냅샷 없음**
     (body=None) — JIF는 장상태 *전환* 시에만 송신(엣지 트리거). 그래서 장중 시작 시 첫 전환까지 폴백.
   - ✅ **장운영 REST 조회 TR은 없음**(전체 364 TR 카탈로그 확인) — 장운영은 JIF(WebSocket)가 유일.
     그래서 시작 즉시 현재 장상태를 LS에 물어보는 방법은 불가 → 폴백을 시각 기반으로 보강(아래 B).
   - ✅ **B: 폴백 동시호가 보강** `current_time_phase()` — JIF 미수신이어도 주간 동시호가(장개시 ~09:00 /
     장마감 15:35~15:45)를 AUCTION으로 보아 신규 주문 차단. 시각 출처: 한국투자증권 업무시간 안내.
     야간 동시호가 시각은 미확정 → 야간은 CONTINUOUS로 두고 JIF가 보정.
   - 📌 **남은 확인**: 모의가 실제 전환 이벤트(jstatus 31/41 등)를 쏘는지 — 마감(15:35~45)/야간시작(18:00) 때 재확인.
   - 검증 예제: `examples/15_jif_listen.py`

4. **WebSocket 시세 전환** — 호가 **`FH9`**(주간 선물호가), 체결통보 **`C01`**, 장운영 `JIF`.
   - ⚠️ **TR 정정(LS 공식 답변 2026-06-23)**: **`FH0`/`FC0`는 폐지 → `FH9`/`FC9`로 대체.** 메모 원본의
     `FH9/FC9`가 맞았는데 카탈로그(3rd-party) 보고 FH0로 잘못 바꿨던 게 `10002 "허용되지 않은 trcd"`의 원인.
     (한도·유령구독·연결묶기 추정 다 틀렸고, 폐지 TR이 원인이었음.) → 코드 FH9로 수정.
   - 📌 **USD선물 호가 FH9 실전달은 장중 검증 필요** — FH9는 거부 안 되나(구독 성공), 장마감엔 데이터 없음.
     FH9가 KOSPI200 전용일 가능성도 있어, 안 오면 **주간 호가는 REST(t2112)가 정상 경로**
     (동작하는 RTD 서버 reference도 통화/상품선물 주간은 REST 사용). 야간은 DH0/DC0.
   - ✅ **broker 폴백 구조**: `get_orderbook()`이 WS 캐시 우선·**비면 REST(t2112)**(페일세이프) →
     FH9가 오든 안 오든 매매는 정상. 단위테스트 `tests/test_broker_routing.py`.
   - ✅ **연결 분리 + 깔끔한 종료**: 그룹별 별도 WebSocket(FH9 / JIF / C01), 종료 시 구독해제(tr_type 4/2)
     + graceful close(`CancelledError`까지 처리)로 유령 구독 방지.
   - ✅ **2단계 포지션 WS 전환 완료(C01)**: ⚠️ **체결통보는 시세(tr_type=3) 아니라 계좌등록(tr_type=1)으로**
     등록해야 함(모의 실측으로 확인 — 이걸 몰라 처음엔 0건이었음). 실측 필드: `dosugb`(2=매수/1=매도),
     `chevol`(체결수량), `expcode`(**표준코드** 'KR4A75670005' — 단축코드 'A756'을 부분문자열로 포함).
     구조: `get_position()` = t0441 시작값(baseline) + C01 누적증감, 주기(30s) t0441 재동기화로 드리프트 보정.
     **end-to-end 실측**(2026-06-23 mock): 매수1→2, 매도1→1, t0441 폴링 없이 실시간 반영. 단위테스트 포함.
   - 📌 **남은 것**: 야간 호가(DH0)·야간 체결통보 추가는 야간 실거래 검증 때. C01 prod 첫 가동 시 dosugb 재확인.
5. **운영 튜닝(폴링)** — 포지션 t0441 폴링은 **C01로 해소**(WS). 주간 호가는 FH9 장중 검증 전까지 REST(t2112)
